## 1. 背景与已核对事实

- 本机 `/Users/echo/.bin/dora` 是 `dora-cli 1.0.0-rc1`。它是**另一个 fork 构建的**，
  与 `dorarobotics-dev/dora` 不保证兼容，因此面板**不硬编码版本**，而是显示实际
  CLI 路径与 `--version` 输出。
- dataflow 必须跑在 **coordinator** 上：`dora up` + `dora start <dataflow>.yaml`。
  `dora run` 使用隔离 coordinator，外部 CLI（以及本面板）查询不到。这一点已写进
  面板空态与 README。
- 实现路线为「Studio 面板 + 调用 CLI 子进程」，**不引入** `dora-node-api`。
- CLI 已具备的命令（`--help` 实测）：`dora list`、`dora topic list/echo/hz`、
  `dora param list/get/set/delete`、`dora node list/info/restart`、`dora logs`、
  `dora inspect top`。本面板只取其中只读子集。

## 2. 能力清单

| 区域 | 能力 |
|---|---|
| 顶部 | 解析并显示 CLI 绝对路径；执行 `--version` 显示实际版本；`dora list` 显示 coordinator 状态 |
| 中段左 | `dora topic list` 刷新 topic 列表，固定 8 个槽位，可选中 |
| 中段中 | 对选中 topic 启动 `Echo` 或 `Hz`；输出滚动显示；`Stop` 取消；同一时刻仅一个流 |
| 中段右 | `dora node list` 刷新 node 列表；选中执行 `node info`，并自动读取该 node 的 param 列表 |
| 中段右下 | 选中 param 执行 `param get`，显示原始结果 |
| 底部 | 最近命令日志（命令、退出码、耗时）；流结束时记录退出码与持续时间 |
| 全局 | 所有命令只读；命令经 argv 数组传递；一次性命令 5 s 超时；流输出进 5000 行有界环 |

## 3. CLI 命令映射（已核对真实参数形态）

核对方式：`dora topic list --help`、`dora topic echo --help`、`dora topic hz --help`、
`dora param list --help`、`dora param get --help`、`dora node info --help`、
`dora node list --help`、`dora list --help`。

| 面板动作 | 实际 argv | 备注 |
|---|---|---|
| 版本 | `dora --version` | 输出类似 `dora-cli 1.0.0-rc1` |
| coordinator 状态 | `dora list` | 失败（连接拒绝）即视为未启动 coordinator |
| topic 列表 | `dora topic list` | `-d/--dataflow` 可选，本面板未传 |
| node 列表 | `dora node list` | 表格输出；解析第一列 |
| node 详情 | `dora node info <NODE>` | node 为位置参数 |
| param 列表 | `dora param list <NODE>` | **不是** `--node <node>` |
| param 值 | `dora param get <NODE> <KEY>` | **不是** `--node <node> <name>` |
| Echo | `dora topic echo <NODE>/<OUTPUT>` | 无 `--duration` 时持续输出 |
| Hz | `dora topic hz <NODE>/<OUTPUT> --window 10 --duration 60` | stdout 非 TTY 时必须 `--duration` |

### 3.1 与任务初稿的差异（实测后按真实 CLI 修正）

1. `param list` / `param get` 使用位置参数 `<NODE>`，没有 `--node` 选项。
2. topic 数据标识是 `node_id/output_id`，不是裸 topic 名。
3. `topic hz` 在管道输出（本面板）下不启用 TUI，**必须**给 `--duration`；否则 CLI
   直接报参数错误。面板固定 60 秒，并提供 `Stop`。
4. `topic echo`/`hz` 需要 dataflow 开启 `_unstable_debug.enable_debug_inspection`，
   已写入 README 与空态说明。
5. `-d/--dataflow` 本轮不暴露；coordinator 上多 dataflow 并存时是已知限制。

## 4. 架构

```text
plugins/dora-cli/
  Cargo.toml          dorobot-plugin-dora-cli（workspace member）
  src/lib.rs          DoraCliPlugin：id dorobot.dora-cli，panel page_dora_cli
  src/cli.rs          只读 CLI 适配层：解析、一次性命令、流式命令、环形缓冲、输出解析
  src/panel.rs        Makepad 面板：列表槽位、选择、流输出、命令日志、主题
  README.md           使用步骤、命令示例、排障
```

- `cli.rs` 只依赖 `std` 与 `serde_json`，不依赖 Makepad / Studio backend，可直接
  单测。
- 子进程统一用 `Command::args` 传参，**不拼 shell 字符串**；`summary()` 里拼接的
  命令串只用于显示。
- 一次性命令：`run_with_timeout` 起子进程，stdout/stderr 各由线程读取，主线程
  5 ms 轮询 `try_wait`；超时 `kill()` + `wait()`，返回 `timed_out = true` 和已捕获
  的部分输出。
- 流式命令：`StreamSession` 持有 `Child` + `Arc<Mutex<RingBuffer>>`；stdout 与
  stderr 各一个读取线程逐行入环，stderr 行加 `[stderr] ` 前缀。`Drop` 时
  `kill()` + `wait()`，因此 Stop、切换流、面板禁用都不会遗留 CLI 进程。
- 面板 `sync` 只做非阻塞轮询：比较环的 `revision`，变化时才复制最新 400 行并重绘；
  一次性命令只在按钮/选择动作里同步执行。

## 5. 前置条件

1. CLI 可解析：`DOROBOT_DORA_BIN` 优先，其次 `PATH` 上的 `dora`；不存在时面板给
   明确错误，而不是静默。
2. coordinator 已启动：`dora up`。
3. dataflow 用 `dora start <dataflow>.yaml` 启动（**不要**用隔离的 `dora run`）。
4. `topic echo`/`hz` 需要 dataflow 的 `_unstable_debug.enable_debug_inspection: true`。
5. 本机权限：CLI 文件可执行；coordinator 监听在本机默认 `127.0.0.1:6013`（本面板
   未提供远程地址输入）。

## 6. 面板交互与空态

| 状态 | 面板行为 |
|---|---|
| CLI 不存在/不可执行 | 顶部显示 `CLI: not found (...)` 与 `DOROBOT_DORA_BIN`/PATH 提示；列表与按钮禁用 |
| coordinator 未启动 | 顶部显示 `Coordinator: not reachable — start it with dora up...` 和 CLI 的首条 stderr；topic/node 区清空 |
| `dora run` 隔离模式 | 同「未启动 coordinator」；中间输出区与 README 明确说明隔离 coordinator 查不到 |
| topic 列表为空 | 提示先启动 graph，并提示 debug inspection 要求 |
| node 未选中 | param 区提示 `dora param list <NODE>` 需要先选 node |
| 表格格式无法解析 | 保留原始输出到 status 文本，不假装列表为空 |
| 流运行中 | 顶部/状态显示 `streaming`、总行数、缓冲区占用、丢弃行数 |
| 流结束 | 记录退出码与持续时间；输出保留，可继续查看 |
| 流输出超过 5000 行 | 环形缓冲丢最旧行，状态显示 dropped 数 |
| 一次性命令超时 | 结果区显示 `Timed out. Partial output: ...`，命令日志标记 timed out |

## 7. 只读边界

**实现**：`--version`、`list`、`topic list`、`topic echo`、`topic hz`、
`node list`、`node info`、`param list`、`param get`。

**明确不做**：

- `param set` / `param delete`；
- `topic pub`；
- `node restart`；
- `dora start` / `stop` / `up`，以及任何 dataflow 生命周期控制；
- 修改 dataflow YAML、写 run 目录；
- 引入 `dora-node-api` 依赖；
- 远程 coordinator / SSH；
- cgroup/CPU 监控（后续）。

面板不要求 `Backend` 增加字段，也不改 collection/control/policy/aisle、`runtime/`
或 `play.rs`。

| 不依赖真实 daemon | 假 `dora` shell 脚本跑全部单测 | `cli.rs` 9 个测试（Unix） |
| 主题/空态不崩 | 宿主测试创建面板并执行一次空态 `sync` | `dora_cli_panel_syncs_empty_state_without_script_errors` |

人工验收建议（需要真实 coordinator，本环境未启动 GUI）：

1. 终端 A：`dora up`；终端 B：`dora start examples/...yaml`（含 debug inspection）。
2. 打开 Studio → 侧栏 **Component debug**，确认顶部路径/版本/coordinator 状态。
3. Refresh Topics → 选 topic → Echo，确认输出持续滚动；点 Hz，确认旧流被取消且
   60 秒后打印最终统计。
4. Refresh Nodes → 选 node，确认 `node info` 与 param 列表；选 param，确认
   `param get` 的值。
5. 停掉 coordinator，点 Refresh coordinator，确认显示未启动提示而不是 panic。

## 10. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| CLI 版本漂移 | 不同 fork 的子命令/参数可能不同（初稿的 `--node` 就与实测不符） | 面板显示路径与 `--version`；参数集中在一个适配层；列表解析失败时显示原始输出；文档记录已核对版本 |
| 输出格式漂移 | `topic/node/param list` 的表格列不是稳定契约 | 同时接受表格与 JSON 的启发式解析；解析失败不丢原始输出 |
| 多 dataflow | 未暴露 `-d/--dataflow`，多图并存时命令可能歧义/报错 | 面板显示 CLI stderr；后续加 dataflow 选择器 |
| Hz 非 TTY 行为 | 管道下 CLI 必须给 `--duration`，且只在结束时打印统计 | 固定 60 秒 + Stop；文档与按钮文案说明 |
| 跨平台 | 单测依赖 Unix shell 假 CLI；Windows 未验证 | PATH 解析已考虑 `dora.exe`；测试用 `cfg(unix)` 隔离；后续补 Windows 假 CLI |
| 权限 | CLI 不可执行、coordinator 端口不可达、dataflow 未开 debug inspection | 面板逐一显示原因；README 排障表 |
| UI 阻塞 | 一次性命令在 UI 线程同步执行，最坏各 5 s（如首次打开 + 两个刷新） | 骨架阶段接受；后续移到后台线程/Signal |
| 流线程 | 子进程若派生孙进程并占用 stdout，Drop 后读取线程可能延迟结束；只 kill 直接子进程 | 正常 dora CLI 不派生长期孙进程；后续可考虑进程组 |
