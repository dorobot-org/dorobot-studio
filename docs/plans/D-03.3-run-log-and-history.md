## 4. 数据模型

### 4.1 run 目录发现

输入：`runtime::runs()`。

规则：

1. 只接受**目录**，名字以 `studio-` 开头；同级的 `exports/`、临时文件、其他目录忽略。
2. `run_id` 就是目录名（例如 `studio-1764130000123`）。
3. 排序：`dora.log` 的 mtime 降序；缺失则用目录 mtime；仍然相同则 `run_id` 字符串降序。
4. 根目录不存在、不可读、为空：返回空列表，界面显示「没有 run」，不是错误弹窗。
5. 单个 run 内部文件缺失是正常状态：日志可能尚未创建，`recording-status.json` 可能
   还没写，`stop`/`failure-*` 可能都没有。

实现：`plugins/diagnostics/src/runs.rs::discover_runs`（第 417 行）。

### 4.2 run 元信息

```rust
pub struct RunInfo {
    pub run_id: String,
    pub dir: PathBuf,
    pub started_ms: Option<u64>,      // 从 studio-<millis> 解析
    pub modified: Option<SystemTime>, // dora.log mtime，回退目录 mtime
    pub status: RunStatus,
    pub failure: Option<String>,      // failure-*.txt 首行，最多 240 字符
    pub dataset: Option<PathBuf>,     // recording-status.json 的 dataset
    pub log_path: PathBuf,            // <run>/dora.log
    pub log_bytes: u64,
}
```

- `started_utc()`：把 `started_ms` 格式化为 `YYYY-MM-DD HH:MM:SS UTC`。面板明确标注
  UTC；本地时区展示待定（见 8.4）。
- `dataset_ready()`：`dataset.is_dir()`。只有目录仍存在时才允许「Open replay」。
- `RunStatus`：
  - `Failed`：存在 `failure-*.txt`；
  - `Stopped`：存在 `stop`；
  - `Unmarked`：两者都没有。**这不代表进程正在运行**；崩溃退出的 run 也会落到这里。
    进程存活探测（`config.json` 的 `owner_pid`/`supervisor_pid` + `kill(pid, 0)`）
    不纳入本轮，避免平台相关代码和误判。
- `failure` 读取失败（权限/编码）不影响 `Failed` 判定，只让提示为空。
- `dataset` 只来自 `recording-status.json.dataset`。文件缺失或字段为 `null` 时为 `None`；
  不做「按 mtime 猜数据集」的隐式关联。

### 4.3 日志行模型

```rust
pub enum LogLevel { Trace, Debug, Info, Warn, Error, Unknown }

pub struct LogLine {
    pub level: LogLevel,
    pub source: Option<String>, // target/module/node/logger
    pub message: String,
    pub ts: Option<String>,     // 原样保留 ISO-8601 或 epoch
    pub raw: String,            // 原始行，用于搜索与无损导出
}
```

显示格式：

```text
<ts> <LEVEL> <source> <message>
```

例如：

```text
2026-11-26T02:31:04.512Z INFO dora_core::node ready
```

`LogLine::display()` 与 `to_export()` 在 `runs.rs` 第 106 行起。

### 4.4 兼容 `--log-format json` 与纯文本

**JSON 对象行**（tracing-subscriber 的常见形状）：

```json
{"timestamp":"2026-11-26T02:31:04.512Z","level":"INFO",
 "fields":{"message":"node ready"},"target":"dora_core::node"}
```

**扁平 JSON**：

```json
{"level":40,"msg":"motor timeout","module":"guard","ts":1730000000000}
```

字段识别：

| 目标 | 依次尝试的字段 |
|---|---|
| level | `level`, `severity`, `level_name`, `lvl` |
| message | `message`, `msg`, `event`, `fields.message` |
| source | `target`, `module`, `source`, `node`, `logger` |
| ts | `timestamp`, `time`, `ts`, `@timestamp` |

数值级别：兼容 `10/20/30/40/50`（trace/debug/info/warn/error）与
`0..=4` 的 log/syslog 风格；未知数值落到 `Unknown`。

JSON 解析失败、或顶层不是对象：退回纯文本解析，不丢行。

**纯文本行**支持：

```text
2026-11-26T02:31:04Z  INFO dora_core::node: ready
[2026-11-26T02:31:04Z INFO sim] started
[ERROR] driver: boom
plain launcher message without a level
```

规则：

1. 可选的括号头或首个时间戳 token 进入 `ts`。
2. 识别 `TRACE/DEBUG/INFO/NOTICE/WARN/WARNING/ERROR/ERR/CRITICAL/FATAL`（大小写不敏感）。
3. `target:` 形式（或括号头内 level 后的裸 token）进入 `source`。
4. 其余部分作为 `message`；没有 level 时 `Unknown`，保留整行。
5. 空行跳过。

`Unknown` 的级别排名按 `Info` 处理，所以启动器纯文本错误在选择「Info」及以上时仍然
可见；导出时 `Unknown` 行写原始文本而不是强加一个级别。这是有意的「不丢信息」策略。

### 4.5 大文件与缺失日志

`read_log_tail(path, max_lines)`（第 525 行）：

- 从文件末尾按 64 KiB 块反向扫描，凑够 `max_lines + 1` 个换行即停止；
- 最多扫描 8 MiB，避免无换行的大文件撑爆内存；
- 若从中间开始，丢弃第一条不完整行；
- 保留最后 `max_lines` 行，`truncated = true`；
- 文件为空 → 空结果，`truncated = false`；
- 文件不存在 → `io::Error`（界面显示「dora.log 缺失/为空」的降级提示，而不是崩溃）。

常量：

- `DEFAULT_TAIL_LINES = 5000`（面板读取上限）；
- 面板显示再截到 400 行、单行 600 字符，避免 Label 过大；
- 导出使用当前已加载、过滤后的全部行（最多 5000 行）。

## 6. 与回放的联动

### 6.1 关联来源

`recording-status.json` 的 `dataset` 字段是唯一权威关联：

- 保存 take 时 runtime 写入最终目标路径（`runtime/src/record.rs:532`）；
- Studio 端本来就用它驱动「打开已保存片段」（`workflow.rs:254`）；
- 本插件只读同一个字段，因此不会引入第二套关联规则。

如果 `dataset` 为空（未保存、已丢弃、运行中断）或目录已移动，则面板只展示日志，
不提供跳转。

### 6.2 跳转实现

```rust
backend.dispatch(Intent::OpenFolder(dataset.clone()));
```

宿主处理路径（`crates/dorobot-studio-core/src/api/files.rs:1030`）：

1. 把该目录设为 library root；
2. 重新扫描；
3. 打开扫描到的第一个数据集；
4. `self.screen = Screen::Play`。

因此「Open replay」等价于用户手动 **Library → Open folder… → 选择该数据集**，只是
省去选目录。回放本身的播放、片段、时间轴、审阅行为完全复用现有实现。

### 6.3 边界

- 只传**数据集目录**，不传 run 目录。run 目录不是数据集，直接打开会得到空库。
- 不修改 `play.rs` 的当前数据集状态；由 `OpenFolder` 走既有后端流程。
- 如果 dataset 目录里 `meta/info.json` 不合法，回放页会按现有逻辑报错；本插件不
  预校验数据集内容，只检查目录存在。
- 不自动播放。用户仍需在 Replay 里按 Play，符合「回放只改录制视图、不发送电机
  指令」的既有约定（USER_GUIDE 第 8 节）。

## 7. 导出

### 7.1 范围与文件名

- 内容：当前 run、当前级别/关键字/来源过滤后的行。
- 文件名：`run-<run_id>-<ts>.log`。
  - `<run_id>` 形如 `studio-1764130000123`；
  - `<ts>` 为导出时刻的 UTC 紧凑格式 `YYYYMMDD-HHMMSS`；
  - 例：`run-studio-1764130000123-20261126-103104.log`。
- 目录：`<runs>/exports/`（与 run 同级，便于整体备份；`discover_runs` 只认
  `studio-*` 目录，不会把 exports 当 run）。
- 编码：UTF-8；每行一个记录；`Unknown` 行原样输出，其余行输出
  `<ts> <LEVEL> <source> <message>`。
- 不覆盖：同一秒内重名会覆盖。若后续需要，可在 `<ts>` 后追加 `-<millis>`。

### 7.2 导出语义

- 导出的是**已加载的尾部**，不是整个文件。若 `dora.log` 超过 5000 行，更早的行
  不在导出里；界面状态行会说明「tail limit 5000」。
- 导出前不脱敏。日志可能包含本机路径、串口、数据集路径；USER_GUIDE 第 14 节已
  提醒分享前自行删减。
- 不做导出进度条；5000 行写盘为毫秒级。失败时 `notice` 显示错误，不 panic。

## 8. 验收映射

### 8.1 issue 标准拆解

> 「回放一段记录并核对状态」

拆成三个可观察结果：

| # | 结果 | 证据 |
|---|---|---|
| A | 能选中一次真实运行，看到它的开始时间、状态、日志 | 面板 run 行 + 元信息 + 日志尾部 |
| B | 能从该运行打开它产出的数据集并播放 | Replay 页显示同一数据集，Play 有画面/信号 |
| C | 能把这次核对所依据的日志过滤并导出 | `<runs>/exports/run-…log` 存在且内容匹配过滤条件 |

### 8.2 演示脚本（约 5 分钟）

前置：本机已安装可用的 native runtime 与 `dora-cli 1.0.1`；准备一段仿真录制。

1. **产生 run**：按现有产品流程启动仿真并录制一段 take，保存到
   `~/DoRobot/Recordings/nano-…`。确认
   `~/Library/Application Support/DoRobot Studio/runs/studio-<millis>/dora.log` 存在。
   （开发构建下 run 位于 `<repo>/tools/aisle-validation/runs/`。）
2. **打开面板**：侧栏选择 **Run diagnostics**。验证：
   - run 列表按新→旧排序，最新一条被选中；
   - 底部显示 `started … UTC` 与状态（通常为 `stopped` 或 `no exit marker`）；
   - 右侧出现日志尾部，至少包含启动/节点相关行。
3. **核对状态**：在 `Level` 选 `Info`，在 keyword 输入 `dora` 或某个节点名，确认
   行数下降；再清空过滤，确认 5000 行上限提示。点 `Refresh`，确认选择仍保持。
4. **打开回放**：底部 `dataset …/nano-…` 显示后点 **Open replay**。验证：
   - 跳到 Replay，数据集卡片/片段列表出现；
   - 选择 episode 并按 Play，画面/信号随时间变化；
   - 记录下该 episode 与日志时间窗口，作为「状态核对」的人工依据。
5. **导出**：回到 Run diagnostics，选 `Error`（或输入关键字），点
   **Export filtered**。验证：
   - `notice` 显示 `Exported N lines to …/exports/run-…log`；
   - 打开文件，行数与界面匹配，级别均不低于所选阈值。
6. **失败/停止分支**：停止仿真后 Refresh，状态应变 `stopped`；如 runtime 写入了
   `failure-*.txt`，状态应为 `failed` 且元信息展示首行。没有 `dora.log` 时面板应显示
   缺失提示而不是崩溃。

### 8.3 自动化证据

- `runs.rs` 16 个单元测试覆盖：缺目录、排序、dataset/stop/failure、坏 JSON、空日志、
  非 JSON、5000 行尾部、过滤、导出、UTC 格式。
- 宿主插件集成测试 `every_builtin_factory_and_toolbox_has_no_script_errors` 会创建
  diagnostics 面板并断言 Makepad VM 无脚本错误；
  `diagnostics_panel_syncs_read_only_without_script_errors` 进一步在空 runs 目录下
  执行一次 `sync`（含主题、空态渲染），断言无脚本错误；
  `toolbox_has_one_entry_per_plugin_…` 断言侧栏多出第 5 个入口。
- 交互点击（run 行、过滤按钮、导出）没有自动化 UI 测试；验收脚本人工覆盖。

### 8.4 时间口径

运行目录名是 Unix 毫秒，面板按 **UTC** 展示。issue 核对时如需要本地时间，先把
UTC 换算到本机时区；本地时区支持列入后续（见 9.4）。

## 9. 风险与待确认口径

### 9.1 日志格式漂移

`dora --log-format json` 的具体字段由 Dora 版本决定。解析器对 tracing 嵌套
（`fields.message`）和扁平字段都做了兼容，但未来 Dora 若改成非 JSON 或数组格式，
会退化为「整行原文 + Unknown」，不会崩。**没有**对 `dora-cli 1.0.1` 之外的版本做
契约测试。缓解：解析失败不丢行；导出保留 raw。

### 9.2 run 与 dataset 的关联

当前只认 `recording-status.json.dataset`。以下场景会缺关联：

- 录制后手动移动/重命名数据集；
- 运行中断，take 未保存；
- 旧版本 runtime 没有写该字段；
- 一个 run 里保存了多个 take（dataset 字段只保留最后一次）。

备选方案（未实现）：

1. 在 `runs/` 与 `datasets/` 之间按 mtime 窗口猜（不可靠，容易错配）；
2. 让 runtime 在 run 目录写一个 dataset 列表（需要改 Dora 侧，超出范围）；
3. 面板增加「Browse…」手动选择数据集（不改 Dora，但多一步交互）。

**待拍板**：是否接受「只关联最后一次保存的数据集」，还是本轮就加手动选择。

### 9.3 运行状态没有存活判定

`Unmarked` 只表示没有 `stop`/`failure-*` 标记，可能是运行中，也可能是崩溃。
`runtime::runs()` 的既有 live 检测（`api/live.rs:23-44`）依赖 `progress.json` 5 秒内
更新和 socket 存在，只适用于 gamepad 仿真，不适合作为通用 run 状态。

**待拍板**：D-03.3 是否接受「文件标记状态」并在文档/界面明确写
`no exit marker`？还是追加 `config.json` 的 PID 存活探测（平台相关、需要处理 PID
复用）？

### 9.4 时间与时区

面板以 UTC 显示开始时间；`ts` 字段保留原始字符串（JSON 里通常是 UTC）。本地时区
需要 `chrono`/`time` 或平台 API；当前工作区没有时间库依赖，为避免新增依赖本轮不做。

### 9.5 大文件与截断

- 只读最后 5000 行；早期错误可能不在 tail 内。
- 只显示最后 400 行；过滤是在 5000 行内存集合上做，不是全文件。
- 8 MiB 上限对无换行文件会截断；单行 600 字符显示上限。
- **待拍板**：是否需要「导出完整 dora.log」或「加载更多行」按钮？本轮按 issue 的
  核对场景，5000 行足够。

### 9.6 导出目录与保留

导出写到 `<runs>/exports/`，不自动清理。用户备份 run 目录时会连导出一起带走；
如果更希望放 `~/Downloads` 或可配置目录，需要口径确认。

### 9.7 宿主注册影响

- 注册后侧栏增加第 5 个入口；面板实例在启动时创建（只建 View，不读日志，因为
  `legacy_screen: None` 且未选中时 `sync` 不会被调用）。
- 既有测试 `toolbox_has_one_entry_per_plugin_instead_of_one_per_panel` 原来断言 4 个
  插件，已更新为 5 并新增标题断言。这是注册新插件的必要维护，不是业务逻辑改动。
- 插件不要求 `Backend` 增加字段；`PanelContext` 的现有字段足够。
- 回滚（见第 12 节）后该测试需同步改回 4。

### 9.8 隐私

日志可能包含用户名、绝对路径、串口、数据集名。面板只读、导出不脱敏。发布说明应
沿用 USER_GUIDE 第 14 节的提醒：分享前删减敏感信息，不要附带 token。

### 9.9 读取发生在 UI 线程

`load_run_log` 同步读最多 8 MiB / 5000 行。对本地 SSD 是毫秒级，但极端慢盘可能掉帧。
骨架阶段接受；后续可把读取移到后台线程，用 `Signal` 回传（与 `RobotModelLoader`
模式一致）。

## 11. 测试与编译验证（实测）

环境：macOS，Rust 1.98.0，sparse clone；本地 cargo 缓存已具备依赖。
所有命令均为 `--offline`，没有联网下载。

| 命令 | 结果 |
|---|---|
| `cargo metadata --no-deps --offline` | 成功；包列表包含 `dorobot-plugin-diagnostics` |
| `cargo check -p dorobot-plugin-diagnostics --offline` | **成功**（0 error；core 有 26 个既有 warning） |
| `cargo test -p dorobot-plugin-diagnostics --offline` | **16 passed, 0 failed** |
| `cargo check -p dorobot-flex --no-default-features --offline` | **成功**（含插件注册） |
| `cargo test -p dorobot-flex --no-default-features --test plugins --offline` | **18 passed, 0 failed** |

重要说明：

- 该副本最初缺少 sparse-checkout 的 `vendor/`，`cargo check` 会失败在
  `[patch] vendor/makepad-urdf-player`。本机从**已有 git object**恢复了
  `vendor/makepad-urdf-player`（`git sparse-checkout add vendor`，未联网、未重新
  下载），之后上述验证才通过。**在缺少 `vendor/` 的干净稀疏克隆上，第一步会失败**，
  需按仓库文档补全 vendor 或使用完整克隆。
- 没有验证默认 `video` feature（FFmpeg）构建；插件本身不依赖 FFmpeg，宿主侧
  `--no-default-features` 已覆盖插件接线。
- 没有启动 GUI 做鼠标交互验收；面板 DSL 的创建由集成测试
  `every_builtin_factory_and_toolbox_has_no_script_errors` 覆盖（会调用
  `create_instance("page_diagnostics")` 并断言 VM 无脚本错误），空 runs 目录下的一次
  `sync` 由 `diagnostics_panel_syncs_read_only_without_script_errors` 覆盖。
- 首次实现时有 1 个借用检查错误（`read_run` 中 `dir` 提前 move）和 4 个测试断言
  错误，已修复并重跑全绿；不是遗留问题。
