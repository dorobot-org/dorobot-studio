# dviz P2 交付①"看"实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** epyc 上的 Studio 连上 Orin 的桥节点，在新的 2D 地图面板和 Rerun 3D 窗口里同时看到 DORA_NAV 的栅格地图、车的足迹、规划路径（绿）、实际轨迹（橙）、目标、激光、点云和导航状态；顺带修好 P1 手动检查的问题 A–C。

**Architecture：**
- **车上桥节点：** `runtime/nav-bridge`，独立 Cargo 工作区，Dora 1.1 节点。把 DORA_NAV 的输出解析、变换到地图系、降采样、限频、配色，经 Zenoh（`tcp/0.0.0.0:7450`，不开组播）发成 dviz 协议。
- **Studio 插件：** 会话里多存一份"导航场景"（每个导航实体的最新值），供新的 `dviz_nav` 面板画 2D 图；可视实体照旧送 Rerun。
- **DORA_NAV：** 只在设置了 `NAV_VIZ_BRIDGE` 时，把桥节点叠加进数据流。

**Tech Stack：**
- Rust：Makepad OctoSense fork `44d8220f`、Zenoh `=1.10.2`、Rerun 0.28、dora-node-api `=1.1.0`、serde_json；
- DORA_NAV 侧：bash 和 Python 3（autostart 叠加）。

**Spec：**
- `docs/superpowers/specs/2026-11-22-dviz-p2-nav-view-design.md`（下称"设计"）；
- 它的前身 `docs/superpowers/specs/2026-11-22-dviz-nav-plugin-design.md`（"P1 设计"）。

## Review Focus

1. **Wi-Fi 断了，或 Studio 卡住、不读数据：** 桥节点的 Dora 事件循环照常、不阻塞，导航不受影响；只是丢数据并计数。测试见任务 10 `slow_subscriber_never_blocks_the_dora_side`。

3. **DORA_NAV 发来坏数据**（激光截断、位姿 NaN、空路径、`"error": true` 的路径）：桥节点跳过、计数，不崩溃；出错的路径会清空 `nav/plan`。测试见任务 8 `bad_inputs_are_skipped_and_counted`、`error_path_clears_plan`。
4. **地图文件缺失或不合法**（YAML 找不到、PGM 尺寸不对、原点带旋转）：桥节点照常启动，只是不发 `map/grid`，并发一条 WARN 日志；2D 视图没有地图时按车和轨迹自动取景。测试见任务 8 `missing_map_is_not_fatal`、任务 7 `fit_without_grid_uses_robot_and_trail`。
5. **重定位跳变、换目标、桥节点停了：** 新目标清空轨迹；状态超过 2 s 没更新，状态行变灰并写"stale"。测试见任务 8 `trail_resets_on_new_goal_id`、任务 7 `status_older_than_two_seconds_is_stale`。
