# dviz P2：在 Studio 里看、操作 DORA_NAV 导航（RViz 式 2D 地图 + Rerun 3D）设计

日期：2026-11-22。上一份设计：`docs/superpowers/specs/2026-11-22-dviz-nav-plugin-design.md`（下称"P1 设计"），本文件在它的基础上细化 P2，冲突处以本文件为准。

## 用户决定（本次讨论）

- 场景：epyc（x86 桌面，和 Orin 在同一个局域网）上跑 Studio，实时看 Orin 上 DORA_NAV 的导航，效果接近 RViz：**规划路径和实际走过的轨迹用不同颜色**，车、地图、激光、点云、目标都显示。
- 要有 RViz 式的 **"2D Pose Estimate"（设初始位姿）和"Goal"（设目标）按钮**。
- 交互方式选 **方案 1**：Studio 窗口里做一个俯视 2D 地图视图，在图上按下、拖出朝向来设初始位姿 / 目标；3D 仍然看 Rerun 窗口。（P1 设计原定 P2 只做表单，这条改掉。）
- 数据通路沿用 P1 设计：**车上桥节点 → Zenoh → Studio 插件**；不让 Studio 直接订阅车上 Dora 节点。
- **分三次交付**，每次单独写计划、做完由用户验收：① 看；② 做；③ 代价地图。

## 意图

在桌面上用 Studio 取代 RViz 看和操作 Tracer Mini 的 Dora 导航：一眼看出车在哪、要去哪、规划怎么走、实际怎么走、看到了什么障碍，并能像 RViz 一样在图上设初始位姿和目标。

## 目标 / 非目标 / 反目标

**目标**

| 交付 | 用户能做到 |
|---|---|
| ① 看 | epyc 上的 Studio 连上 Orin 的桥节点，在 **2D 地图视图**和 **Rerun 3D 窗口**里同时看到：栅格地图、车的足迹和朝向、规划路径、实际轨迹、当前目标、激光、降采样的点云；Rerun 里另有 PCD 点云地图；2D 视图有一行紧凑状态（定位、安全门、底盘、目标状态）。另外修好 P1 手动检查发现的 3 个问题。 |
| ② 做 | 在 2D 地图上用"2D Pose Estimate""Goal"设初始位姿、发目标；"急停""撤防"按钮；导航状态面板显示命令回执和目标进展。 |
| ③ 代价地图 | DORA_NAV 规划器输出代价地图，2D 视图和 Rerun 都能叠加显示。 |

**非目标**
- 画在 Studio 窗口里的 3D（以后单独设计）。
- 在 Rerun 窗口里点选（Rerun 0.28 没有把查看器鼠标事件送回程序的接口）。
- 改变 DORA_NAV 的导航行为；M6 巡检桥；Gazebo 替代。
- 多机器人同时显示（协议留了 `robot_id`，界面只做一台）。

**反目标（做出来也算失败）**
- 能从车外武装或解除急停。
- 桥节点拖慢、阻塞导航数据流，或者 Studio / Wi-Fi 卡住时车上导航受影响。
- DORA_NAV 硬依赖 Studio：不设置桥节点时，数据流和现在完全一样。
- 破坏 Studio 现有插件、测试和 `--locked` 构建。

## 约束

- P1 设计"约束"一节全部有效（Makepad 固定版本、插件 API 1、Zenoh `=1.10.2`、Rerun 0.28、`--locked`、桥节点用 dora-node-api 1.0.1、放 Studio 的 `runtime/`、许可证）。
- **DORA_NAV 的数据**（`apps/tracer/tracer_nav.yml`，Dora 1.1，全是 UInt8 字节数组）：

  | 用途 | 输出 | 格式 |
  |---|---|---|
  | 车的位姿（地图系） | `pose_fuser/map_base` | Odometry JSON |
  | 规划路径 | `astar_planner/path` | `{"header","goal_id","poses":[{"x","y"}],"error"}` |
  | 当前目标 | `goal_resume/goal` | `{"id","source","x","y","yaw"?}` |
  | 目标状态 | `pure_pursuit/goal_status` | `{"id","state","reason"}` |
  | 激光（由点云压成） | `cloud_to_scan/scan` | LaserScan 二进制（28 字节头 + f32 距离），车体系 |
  | 点云 | `super_lio/cloud_body` | `[f64 stamp][u32 N][N×4 f32 XYZI]`，车体系 |
  | 定位可信度 / 重定位 | `loc_trust/status`、`loc_refine/state` | JSON |
  | 安全门 | `cmd_gate/state`、`cmd_gate/cancel` | JSON |
  | 底盘 | `tracer/state` | JSON |

- **地图文件：** 规划器配置 `astar_planner_tracer.json` 的 `map_yaml`（现为 `garage_20261121/map.yaml`：`trinary`，0.05 m，原点 `[-3.95, -6.25, 0]`，PGM 187×208）；PCD 在 `loc_refine` 的 `MAP_PCD`。桥节点按配置读，不写死。
- **车的足迹：** `base_footprint` 是转向中心，在车头后 0.09 m；车身 0.40 × 0.40 m，所以足迹多边形（`base_footprint` 系）是 x ∈ [−0.31, 0.09]，y ∈ [−0.20, 0.20]。
- **网络：**
  - Orin 的 7447 端口已被占用；
  - 车上 Dora 节点会用组播发现，主动连局域网里的 Zenoh 对端（P1 手动检查时，它们连上了 epyc 上的 Studio）。
  - 所以桥节点用**单独的端口**（我定 `tcp/0.0.0.0:7450`），**关闭组播**；Studio 用 `client` 模式填 `tcp/<Orin IP>:7450`（Orin 现在是 192.168.1.186）。
- **带宽：** Wi-Fi，桥节点总发送量目标 ≤ 1 MB/s。
- **命令：** 车上 `nav_command` 只听 `127.0.0.1:9998`（UDP），已支持 `goal {x,y,yaw?}`、`initialpose {x,y,yaw}`、`estop`、`disarm`（还有 `arm`、`release`，车外禁止）。
- **Studio 2D 绘制：** 贴图照 `crates/dorobot-studio-core/src/widgets/video_player.rs`（`Texture::new_with_format` + `set_texture`）；拖动照 `time_series_plot.rs`（`Hit::FingerDown/Move/Up`）；节点图 `plugins/dviz/src/graph.rs` 已有自绘和点选的写法。
- **Rerun 0.28：** `Transform3D` 本身不画东西，要显示坐标轴得另写 `TransformAxes3D`。

## 方案（已选定 1）

1. **车上桥节点（选定）：** 桥节点挂进 DORA_NAV 数据流，把上表的输出整理成 dviz 协议，降采样、限频、配好 RViz 式颜色，经 Zenoh 发出；实际轨迹也在车上记，晚连上的 Studio 也能看到。Studio 插件一份数据画两处：Rerun 窗口（3D）和新的 2D 地图视图。命令反向走同一个桥节点。
2. **Studio 直接订阅车上 Dora 节点的 Zenoh（不选）：** 看起来省掉桥节点，但那是 Dora 内部格式、点云原样走 Wi-Fi，远端订阅者还可能反过来拖慢车上发布数据的节点，违反反目标。
3. **2D 视图用网页画布（不选）：** 和 Studio 写法不一致，按钮和状态要维护两份。

## 设计

### 1. 协议补充（`crates/dviz-protocol`）

- **新类型 `grid2d`：**
  - JSON 头 `{"width","height","resolution","origin":[x,y,yaw],"kind":"occupancy"|"costmap"}`；
  - 二进制载荷：`width×height` 个 u8，行优先，第 0 行是地图 y 最小的一行（和 PGM 上下相反，桥节点负责翻转）。
  - `occupancy` 取值：0 空闲、100 占用、255 未知。`costmap`（交付 ③）用 Nav2 语义：0–252 代价，253 内切，254 致命，255 未知。
- **新类型 `status`（导航状态，合成一条）：**
  - 定位：可信 / 不可信、原因；
  - 安全门：武装 / 撤防、原因；
  - 底盘：控制模式、是否武装、原因；
  - 目标：id、状态、原因；
  - 速度：v、ω；
  - 命令：目标 / 初始位姿是否已开放（交付 ②，见 §5）。

  具体字段由实现者从 DORA_NAV 的 JSON 里挑。
- **新类型 `cmd` / `cmd_ack`（交付 ②）：** 见 §5。
- 现有 `points3d` / `linestrips3d` / `arrows3d` / `transform3d` 的颜色字段直接用来表达 RViz 式配色，不加新类型。
- 解码、校验和往返测试照 P1 的做法；超大或畸形数据被拒，不崩溃。

### 2. 实体和配色（桥节点发出，插件照着画）

所有几何数据都在**地图系**（`map`），由桥节点用最新的 `map_base` 把车体系数据变换过去。2D 视图和 Rerun 都不用再解析坐标树。

| 实体 | 类型 | 内容 | 颜色（RViz 习惯，我的选择） | 频率上限 |
|---|---|---|---|---|
| `map/grid` | `grid2d` occupancy | 栅格地图 | 空闲近白、占用黑、未知中灰（和 map_server / RViz 显示 PGM 一样） | 启动时一次，之后每 5 s 补发 |
| `map/cloud` | `points3d` | PCD 地图，体素抽稀到 ≤ 50k 点 | 浅灰，小点 | 每 10 s 补发 |
| `robot/pose` | `transform3d` | 车在地图系的位姿 | — | 20 Hz |
| `robot/footprint` | `linestrips3d` | 足迹多边形（已变换到地图系）+ 车头方向短线 | 绿色轮廓 | 20 Hz |
| `nav/plan` | `linestrips3d` | 规划路径 | 绿色（Nav2 全局路径的习惯） | 有新路径时 |
| `nav/trail` | `linestrips3d` | 实际轨迹：**从当前目标开始**，每走 ≥ 5 cm 记一个点，最多 3000 点；收到新目标时清空 | 橙色 | 2 Hz |
| `nav/goal` | `arrows3d` | 当前目标的位置和朝向；没有目标时发空 | 品红 | 有变化时 + 每 2 s |
| `sensors/scan` | `points3d` | 激光（变换到地图系） | 红色 | 10 Hz |
| `sensors/cloud` | `points3d` | 实时点云，抽稀到约 5k 点 | 按高度着色（由插件着色，见 §3） | 5 Hz |
| `nav/status` | `status` | 合成的导航状态 | — | 5 Hz + 有变化时 |
| `costmap/global`（交付 ③） | `grid2d` costmap | 规划器代价地图 | RViz costmap 配色 | 1 Hz |

- 颜色在桥节点的配置里可改；上表是默认值。
- **"实际轨迹从当前目标开始"是我的选择：** 这样一眼就能对比"这一趟规划的"和"这一趟实际走的"。没有目标时也照样记，直到下一个目标清空。
- 车上日志和数据流图照 P1 设计 §3（跟踪 `out/<uuid>/log_<node>.jsonl`，限流，图来自数据流 YAML）。

### 3. Studio 插件

- **Rerun 侧：**
  - `transform3d` 额外写 `TransformAxes3D`（修 P1 问题 A），轴长 0.3 m；
  - `grid2d` 画成地面上的贴图四边形（Rerun `Mesh3D` 加纹理；做不出来就退回"占用格画成点"，由实现者在计划里定）；
  - `sensors/cloud` 按 z 着色；
  - 根实体设成 Z 朝上的右手系。
- **新面板 `dviz_nav`（"Navigation"）**，和 P1 的 `dviz_view` 共用进程级会话：

```
┌ Navigation ───────────────────────────────────────────────────────────────┐
│ [适应地图] [跟随车]  │ [2D Pose Estimate] [Goal]  │ [急停] [撤防]   ② 才有  │
│ 定位 ✔ 可信 · 安全门 撤防(disarm) · 底盘 CAN · 目标 #12 执行中 · 0.20 m/s │
│ ┌───────────────────────────────────────────────────────────────────────┐ │
│ │  ░░░░░░░░░░░░░░░░███████░░░░░░        图例（可开关）：                  │ │
│ │  ░░░░ ·:·  红色激光  ░░░░░░░░░░        ■ 地图  ━ 规划(绿) ━ 实际(橙)    │ │
│ │  ░░░░  ━━━━━━━━━━━━━━━━━━▶ 品红目标      □ 车(绿) · 激光(红) ▶ 目标     │ │
│ │  ░░░░  ┅┅┅┅┅ 橙色实际  □→ 车           Wi-Fi 急停不是安全装置           │ │
│ └───────────────────────────────────────────────────────────────────────┘ │
│ 回执：goal #13 已转给 nav_command（ok）                         ② 才有      │
└───────────────────────────────────────────────────────────────────────────┘
```

- **2D 视图（交付 ①）：**
  - 绘制：栅格地图画成贴图，其余画成矢量线和点，按上表配色；
  - 操作：滚轮缩放（以光标为中心）、拖动平移；
  - 按钮："适应地图""跟随车"（车保持在中心）；
  - 图例里的每一层都能开关；
  - 刷新：跟随会话快照，约 10–20 Hz，不在界面线程等网络。
- **2D 工具（交付 ②）：**
  - 点"2D Pose Estimate"或"Goal"进入对应工具；
  - 在图上按下定位置、拖动定朝向，松开就发送；按 Esc 或再点一次按钮取消；
  - 拖动时画预览箭头：初始位姿绿色，目标品红；
  - 发送后工具自动退出（和 RViz 一样）；
  - 回执显示在面板底部。
- **按钮：** "急停""撤防"一直可见（交付 ②）；没有"武装""解除急停"。
- **状态行：**
  - 来自 `nav/status`；
  - 超过 2 s 没收到，整行变灰，写"状态过期"；
  - 面板上写明"Wi-Fi 急停不是安全装置，遥控器切 RC 才是"。

### 4. 车上桥节点（`runtime/` 新二进制，名字由实现者定，例如 `dorobot-nav-bridge`）

- **独立工作区（我的决定，审查后补充）：**
  - **冲突：** `runtime/` 现有工作区因为 dora-node-api 1.0.1 锁在 Zenoh 1.9.0；Studio 插件用 Zenoh `=1.10.2`。一个二进制里放不下两个 Zenoh 1.x 版本，而 `runtime/` 里现有的 Nano / SO101 程序又要求 Dora 1.0.1，不能整体升级。
  - **做法：** 桥节点放在 `runtime/nav-bridge/`，单独一个 Cargo 工作区和 `Cargo.lock`，用 dora-node-api `=1.1.0`（和车上 Dora 1.1.0 一致，要求 Zenoh 1.10）和 Zenoh `=1.10.2`，按路径依赖 `crates/dviz-protocol`。
  - **影响：**
    - 构建一律 `--locked`；
    - 不进 Studio 根工作区，所以不影响 Studio 的 CI 和锁文件；
    - 桥节点和 Studio 用同一个 Zenoh 版本，不需要跨版本互通测试。
  - 这条修正 P1 设计里"桥节点用 dora-node-api 1.0.1"的写法：那句的本意是"Dora 1.1 守护进程能接受的 1.x 节点 API"，1.1.0 同样满足。
- **处理：** 照 P1 设计 §3：有界队列、满了丢最旧的；在 Dora 事件循环外处理；Zenoh 发不出去不阻塞；没人订阅时只做最少的工作。
- **Zenoh：**
  - peer 模式，监听 `tcp/0.0.0.0:7450`（可配置）；
  - 关闭组播；
  - 话题前缀 `dviz/<robot_id>`，默认 `dviz/tracer`。

  Studio 侧的 Prefix 填 `dviz/tracer`，或者由实现者把前缀约定好写进文档。
- **配置：** 一个 JSON / TOML 配置，内容包括：
  - 输入名到格式的映射；
  - 地图 YAML / PCD 路径；
  - 颜色、限频、端口、`robot_id`、命令通道开关、令牌路径。
- **接进数据流（DORA_NAV 改动，小）：**
  - `apps/tracer/autostart.sh` 只在设置了 `NAV_VIZ_BRIDGE=<桥节点路径>` 时，由 `tracer_nav.yml` 加上一个桥节点叠加片段，生成 `out/tracer_nav.viz.yml` 再启动；没设置时和现在完全一样。
  - 环境变量由 `dora-nav.service` 读一个可选的环境文件（例如 `EnvironmentFile=-%h/.config/dora-nav/env`）。具体写法由实现者定，但"不设置就和现在一样"必须有测试或演练证明。
- **地图来源：** 地图 YAML 路径来自配置（默认读规划器配置里的 `map_yaml`）；PGM 按 `trinary` 规则转成 occupancy。

### 5. 命令（交付 ②）

照 P1 设计 §3"命令"和 §5"安全"，补充：
- **请求：** Studio 发到 `dviz/<robot_id>/cmd`，格式 `{"cmd","id","token"?,"x","y","yaw"}`；`id` 由 Studio 生成，回执带回同一个 `id`。
- **桥节点：**
  - **急停、撤防总是转发（用户 2026-11-22 决定）：** 只要桥节点在跑，`estop`、`disarm` 就转发，不要令牌，不受开关影响。
  - **命令通道开关只管 `goal`、`initialpose`：** 默认关闭，由车上的配置显式打开；打开后还要令牌。
  - `arm`、`release` 和其他命令一律拒绝；
  - `nav/status` 里带上"目标 / 初始位姿是否已开放"。没开放时，Studio 把两个工具灰掉，并写明原因（"车上未开放"或"本机没有令牌"）。
  - 转给 `127.0.0.1:9998`，把 `nav_command` 的 `{"ok":...}`、超时或拒绝原因发到 `dviz/<robot_id>/cmd_ack`。
- **令牌：** 车上和操作员机器各放一份 `~/.config/dviz/cmd_token`（权限 600）。Studio 启动时读它；读不到时，设初始位姿和目标两个工具灰掉，提示原因。
- **限流：** `goal` / `initialpose` 每秒最多 2 条；`estop` / `disarm` 不限流。

### 6. P1 手动检查发现的问题（并入交付 ①）

- **A：** 位姿在 Rerun 里看不见。`transform3d` 加写 `TransformAxes3D`。
- **B：** 深色主题下 dviz 面板的文字看不见，切回浅色后面板也不恢复。要求：
  - 两个面板的所有文字和背景都跟主题走；
  - 来回切换后能正确恢复；
  - 加回归测试（至少测主题值被套到了每个需要的控件上）。
- **C：** `docs/DVIZ.md` 的查看器安装改成 `pip install rerun-sdk==0.28.2`（建议放进单独的 venv）。原写法 `cargo install rerun-cli` 在 Rust 1.95 上编译失败。另外注明：组播模式下的"Connected"可能是别的 Zenoh 节点（比如车上的 Dora 节点），连车请用 `client` 模式填端点。

## 测试

- **单元测试（先写失败的测试）：**
  - **协议：** `grid2d` / `status` / `cmd` / `cmd_ack` 往返，坏数据被拒。
  - **桥节点：**
    - 每种 DORA_NAV 格式的解析；
    - 车体系到地图系的变换；
    - PGM 转 occupancy（含上下翻转）；
    - 足迹多边形；
    - 轨迹的 5 cm 间隔、3000 点上限、新目标清空；
    - 降采样上限、限频；
    - 命令过滤和令牌、回执（交付 ②）。
  - **插件：**
    - 2D 视图的坐标换算（地图 ↔ 屏幕、缩放、平移）；
    - 拖动换算成位置和朝向；
    - 图层开关、状态过期；
    - 工具状态机（交付 ②）；
    - 主题套用（问题 B）。
- **离线集成（不动车）：** 照 P1 设计"测试"一节的两个数据流：
  - **(a) 录包回放加桥节点：** 再起一个无界面的订阅者，核对话题齐全、频率、点数、带宽 ≤ 1 MB/s。
  - **(b) 2D 仿真加命令入口（交付 ②）：** 从订阅者或 Studio 发目标，仿真车到点；`arm` / `release` 被拒；没有令牌的 `goal` 被拒；不带令牌的 `estop` 被接受。

  回放数据流和车上正在跑的 dora-nav 会争 `127.0.0.1:9998` 和节点名，所以要么换端口，要么先停 dora-nav（停之前问用户）。
- **epyc 端到端：**
  - **交付 ①：** Studio 先连 (a)，再连实车，两个视图都能看到全部图层；按 P1 的手动检查方式截图核对。
  - **交付 ②：** 在仿真 (b) 里用 2D 工具发目标、设初始位姿。
- **实车（每次动车都要用户先说 go）：**
  - **交付 ①：** 给 dora-nav 加上桥节点要重启它，会让底盘重新进入 CAN 模式，**先问用户**；车静止时看全部图层；用户同意后，用 `tracer_ctl` 发一个短目标，看规划路径（绿）和实际轨迹（橙）。
  - **交付 ②：** 从 Studio 设初始位姿；发短目标，车到点；行驶中从 Studio 急停；断网时导航不受影响。
