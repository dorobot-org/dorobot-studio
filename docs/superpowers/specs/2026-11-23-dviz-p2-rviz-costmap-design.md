# dviz P2 交付③：RViz 外观、Rerun 改进和代价地图 设计

日期：2026-11-23。在 `docs/superpowers/specs/2026-11-22-dviz-p2-nav-view-design.md`（下称"P2 设计"）基础上补充；冲突处以本文件为准。交付①已完成（Studio `feat/dviz-p2` 14524d2，DORA_NAV `feature/viz-bridge` 2ebe6b5，桥节点已部署在车上）。

## 用户决定（2026-11-23）

- **画面全按 RViz / Nav2：**
  - 深灰背景加 1 m 网格；
  - RViz 的 map 和 costmap 调色板；
  - 全局规划浅蓝、实际轨迹绿、目标橙黄圆环加箭头、车带红色位姿箭头；
  - 定位不可信时车框变红；激光红点。
  - Rerun 用同一套颜色。
- **顺序：** 先做本交付（开机小问题 + 外观 + Rerun 改进 + 代价地图），再做交付②（Pose Estimate / Goal 按钮、急停 / 撤防）。
- **epyc 上的新要求：**
  - Rerun 里点云太密、看不清车，要能关；
  - Rerun 里的车要是 Tracer Mini 的 3D 模型；
  - 线太细；
  - 2D 和 Rerun 都要有 RViz 那样的网格。
- AMCL 粒子云做不了：车上是 hdl 定位，没有粒子。用"定位不可信时车框变红"代替。

## 目标 / 非目标 / 反目标

**目标**

| 部分 | 内容 |
|---|---|
| A 开机小问题 | 修复交付①复审留下的 3 个小问题（见 §A） |
| B 代价地图 | DORA_NAV 规划器输出全局代价地图，桥节点转发；2D 和 Rerun 按 RViz costmap 调色板叠加 |
| C 2D 外观 | 深灰画布、1 m 网格、RViz map 调色板、新颜色和线宽、目标圆环、红色位姿箭头、定位不可信时车框变红 |
| D Rerun 改进 | 新颜色和线宽、1 m 地面网格、点云变小变淡、PCD 地图默认不发、关掉的实体从 Rerun 清掉、Tracer Mini 3D 模型 |

**非目标**
- 交付②的按钮和命令。
- 局部代价地图（DORA_NAV 没有局部规划器的代价地图；`pure_pursuit` 只做碰撞停车区）。
- 机器人模型里的相机、激光雷达支架和关节动画，只画车体和四个轮子，轮子不转。
- 2D 视图里的 3D 模型（2D 仍画足迹）。

**反目标**
- 规划器因为多发一个输出而变慢，或者行为改变（路径、重规划节奏）。
- 车上开机比现在更容易失败。
- Wi-Fi 带宽超过 1 MB/s（P2 设计的上限）。

## 约束

- P2 设计和交付①计划的全局约束仍然有效：Makepad 版本、`--locked`、Zenoh `=1.10.2`、Rerun 0.28、桥节点独立工作区、不拖累导航、提交身份。
- **DORA_NAV 规划器：**
  - `modules/planner/nav_costmap/src/costmap2d.h` 的 `Costmap2D` 按 Nav2 语义：0 空闲，1–252 膨胀，253 内切，254 致命，255 未知；
  - `GlobalPlanner::costmap()` 能取到它；
  - 地图 187×208，0.05 m；
  - 规划器每 1 s 重规划，激光通过 `onScan` 写进障碍层。
- **Tracer Mini 模型（审查后核实）：**
  - 网格在 `~/nvme/tracer_ws/src/tracer-mini-ros2/tracer_mini_description/meshes/`，单位米；`base_link.STL` 85 014 个三角形、4.2 MB，包围盒 x −0.205…0.223、y ±0.208、z −0.188…0.084。
  - 这些 STL 是按装配坐标导出的，还没修好：轮子文件的坐标轴约定和车体不同，一个文件里不止一个轮子；仓库的 HANDOFF 写着"不要靠外观猜位置"。
  - 真车 URDF（`tracer_mini_real.urdf.xacro` / `tracer_mini_macro.xacro`）里，车体是方块（0.40×0.40×0.112 m），轮子是圆柱（r 0.065 m），并没有引用 STL。
  - 太大，不能走 Wi-Fi。
- **RViz 调色板**（来自 RViz 源码 `map_display.cpp`）：
  - map：占用值 0–100 线性映射为白到黑（`v = 255 − 255·i/100`），未知为 `#708986`；
  - costmap：0 透明；1–98 从蓝到红（`v = 255·i/100` → `(v, 0, 255−v)`）；99（内切）青 `(0,255,255)`；100（致命）紫 `(255,0,255)`；未知 `#708986`。
  - Nav2 的代价换算成 RViz 的 0–100 刻度，照 Nav2 costmap 发布时的做法：0→0，253→99，254→100，255→未知，1–252→1–98 线性。
- **Rerun 0.28：** `LineStrips3D` / `Points3D` 支持 `radii`；`Asset3D` 能显示 STL；`Clear` 能清掉实体。

## 方案

**机器人 3D 模型怎么到 Studio：**
1. **Studio 自带精简后的模型（选这个）：** 离线把车体 STL 精简到 ≤ 1 MB，打包进 dviz 插件。桥节点在配置里声明 `robot_model: "tracer_mini"`，通过 `nav/status` 或一条静态消息告诉 Studio。Studio 把模型挂在车的位姿下面。不占 Wi-Fi。
2. **桥节点通过 Zenoh 发模型：** 精简后也要占带宽；晚连上的 Studio 要重发；插件还得会解析 STL 字节流。
3. **Studio 从本地 URDF 路径加载：** epyc 上没有 tracer_ws，每台机器都要配路径。

**Rerun 网格：** Rerun 0.28 的 3D 视图有 `LineGrid3D` 设置。如果 Rust SDK 能方便地发 blueprint，就用它；否则在地面上记一组静态的 1 m 线（`world/grid`），由实现者在计划里定。

## 设计

### A. 开机小问题（交付①复审的 3 个小问题）

1. `autostart.sh`：`NAV_VIZ_START_WAIT` 不是正整数时，打印原因，按默认 20 s 处理。
2. `autostart.sh`：带桥节点的数据流 `dora start` 返回非零时，先执行和"没进入 Running"相同的"停掉 + 等到没有 Running 的 tracer-nav"，再起原数据流。
3. 桥节点 README 里数据流的例子改用安装目录；`install.sh` 的路径白名单和 `viz_overlay.py` 的一致。

每一条都要有 pytest 或 Rust 测试；测试照旧先把假的 `dora` 放在 PATH 最前面。

### B. 代价地图

- **DORA_NAV（`astar_planner_dora`，新分支，叠在 `feature/viz-bridge` 上）：**
  - **新输出 `costmap`：** 每 1 s 最多发一次，并且只在代价真正变了时发（比较哈希），另外每 5 s 补发一次，让晚连上的 Studio 也能看到。
  - **不降采样（我的决定，审查后修改）：** 保持 0.05 m 一格，187×208 ≈ 39 KB。原因是 Tracer 的内切半径只有 0.09 m，0.05 m 栅格上青色内切带只有一格宽；按 2×2 取最大降采样后，青色带只会剩下墙的一侧。按 ≤ 1 Hz、只在变化时发计算，最多约 39 KB/s，加上交付①实测的 361 KB/s，仍在 1 MB/s 以内。
  - **格式：** 小端二进制头（时间戳、宽、高、分辨率、原点 x / y / yaw）加 `w×h` 个 u8，Nav2 语义；第 0 行是 y 最小的一行。头的具体字节布局由实现者定，写进 `msg/` 的格式说明。
  - **不影响规划：** 编码和发送放在重规划之后，耗时要测；规划路径和节奏不能变（现有 ctest 不变，另加编码测试）。
  - **接线（我的决定，审查后修改）：**
    - `tracer_nav.yml` 里规划器改为 `outputs: [path, costmap]`。`viz_overlay.py` 的数据源检查只认基础数据流里声明过的输出；不声明的话，叠加会被拒绝、桥节点整个退掉。
    - 不带桥节点时这个输出没人接，导航行为不变。P2 的反目标"不设置 `NAV_VIZ_BRIDGE` 时数据流和现在完全一样"指的是叠加机制不改动基础数据流；基础数据流本身随本交付多一个输出，用 ctest 和一次不带桥节点的启动来证明行为不变。
    - 叠加模板 `viz_bridge.yml.in` 增加第 11 个输入 `costmap ← astar_planner/costmap`；`test_overlay_sources_are_outputs_of_the_real_dataflow` 会一起覆盖它。离线回放数据流也加上。
- **桥节点：**
  - 新输入格式 `CostmapU8`；
  - 转发为 `grid2d`（`kind: costmap`），实体 `costmap/global`，频率上限 1 Hz；
  - 补发周期和 `map/grid` 一样是 5 s。
- **Studio：**
  - 2D 和 Rerun 都按上面的 RViz costmap 调色板，叠在地图上方，透明度默认 0.5；
  - 图例里加 "Costmap" 开关，默认打开；
  - Rerun 里把它画成比地图高 1 cm 的贴图。

### C. 2D 外观（Navigation 面板）

| 元素 | 画法 |
|---|---|
| 画布 | 深灰 `#303030`，两种主题都一样 |
| 网格 | 1 m 一格，`(160,160,164)`，不透明度 0.5，铺满可见区域，跟着缩放和平移 |
| 地图 | RViz map 调色板：空闲白、占用黑、未知 `#708986`，不透明度 0.7，透出一点背景，空地呈浅灰 |
| 代价地图 | 见 §B |
| 全局规划 | 浅蓝 `(0,180,255)`，4 px |
| 实际轨迹 | 绿 `(0,220,0)`，3 px |
| 目标 | 橙黄 `(255,170,0)` 圆环，半径 0.15 m，最小 10 px；有朝向时加 0.5 m 箭头；没有朝向时只画圆环（取代交付①的十字） |
| 车 | 足迹框：浅灰 `(220,220,220)`，2 px，内部半透明深灰。红色位姿箭头 `(255,25,0)`，长 0.4 m。定位不可信或定位状态过期时，足迹框变红 `(255,0,0)` |
| 激光 | 红 `(255,0,0)`，3 px 方点 |

- **颜色从哪来：** 新的默认颜色写在桥节点配置里，经消息里的颜色字段传过来；Studio 没收到颜色时用同样的默认值。画布、网格、地图和代价地图的调色板由 Studio 自己决定，不经网络。
- **图例：** 跟着新颜色，加 Costmap 一项。

### D. Rerun 改进

- **颜色和线宽：**
  - 规划 `radii` 0.025 m，轨迹 0.02 m，足迹 0.01 m；
  - 目标画成橙黄圆环（线条）加箭头；
  - 位姿除了坐标轴，再加一个红色箭头。
- **网格：** 1 m 地面网格，铺满地图范围，颜色同 2D。
- **点云：**
  - 实时点云 `radii` 0.01 m，按高度着色，不透明度 0.6；
  - PCD 地图 `map/cloud` 默认不发：Displays 里默认不勾选，勾上才发。
- **关掉即清除：** Displays 里取消勾选一个实体时，Studio 往 Rerun 记一条 `Clear`，不再停在最后一帧（P1 遗留的小问题）。
- **Tracer Mini 3D 模型（用户 2026-11-23 决定：只用车体 STL，对齐足迹）：**
  - **离线准备：** 一次性脚本（放进仓库）只处理 `base_link.STL`：
    - 精简到 ≤ 1 MB（顶点聚类或同类算法）；
    - 按包围盒对齐到足迹：水平中心对准足迹中心（`base_footprint` 系的 x = −0.11、y = 0），底面贴地（z = 0）；
    - 朝向：网格的 x 沿车头方向（包围盒较长的轴是 x，0.428 m），先按这个假设做。
  - **许可证：** 在 NOTICE 里写明来源（tracer-mini-ros2，源头可能是 AgileX）和许可证，由实现者核实；不允许再分发就停下来报告。
  - **挂接：** Studio 收到 `robot_model: "tracer_mini"` 后，把模型以静态记录挂在车位姿实体下面（例如 `tracer/robot/pose/model`），随位姿移动，颜色深灰。
  - **验收：** 在 epyc 上截图给用户看朝向和位置；不对就退回"URDF 原样的方块车体 + 4 个圆柱轮子"（尺寸取自 `tracer_mini_macro.xacro`，摆放对齐实车足迹）。
  - **不做：** 不改 tracer-mini-ros2 仓库，不用四个轮子的 STL。
  - **2D：** 不变，仍画足迹。

## 测试

- **A：** pytest 覆盖两种 autostart 情况（等待时间不是整数、viz 启动返回非零后先停再起），以及 install.sh 的白名单。
- **B：**
  - DORA_NAV：代价地图编码的 gtest（行序、头、不降采样的尺寸）；规划器节奏不变（现有 ctest 307 条仍过）；编码耗时 < 2 ms（Orin）。
  - 桥节点：解析、转发、补发。
  - Studio：Nav2 代价到 RViz 刻度的换算、调色板的取值（0、1、98、99、100、未知）。
- **C、D：** 坐标与颜色的纯函数测试（网格线位置随缩放、圆环、红色箭头、定位不可信变红）；Rerun 用内存记录检查组件（`radii`、`Clear`、`Asset3D` 挂在位姿下）；插件资源加载测试（模型文件存在、≤ 1 MB、能解析）。
- **离线回放：** 探测程序新增 `costmap/global` 的期望（≤ 1.1 Hz，存在），总带宽仍 ≤ 1 MB/s。
- **实车（主控执行，每步你同意）：**
  - 重启 dora-nav 带新规划器和新桥节点；
  - epyc 截图核对 2D 和 Rerun；
  - 你说 go 后发一个短目标，看规划、实际轨迹和代价地图。
