# 契约：3D 渲染目标的生命周期（Render Target Lifecycle）

**Feature**: 001-fix-ghost-outline | **Status**: Draft | **Covers**: FR-001、FR-002、FR-004、R2 次修

本契约规定 3D 视图离屏渲染目标在每一帧必须经历的状态，以及"尺寸变化"与"重录制"两类事件的处理方式。它是 `visual-invariant.md` 之外的**第二道防线**：即使门控因故失效，附件本身也不应携带上一帧的内容。

## 1. 每帧必须成立

| # | 要求 | 违约后果 |
| --- | --- | --- |
| L-1 | `pass_size = viewport_size × SSAA_SCALE`，且由**当帧**视口尺寸派生 | 尺寸变化后出现旧画面片段（FR-004） |
| L-2 | 颜色附件在绘制几何前完整清零为 `(0,0,0,0)` | 旧颜色泄漏 |
| L-3 | 深度附件在绘制几何前完整清零为 `1.0` | 深度残留 → 轮廓残留（本 bug 的 A 类） |
| L-4 | 一帧内几何绘制只发生一次（逐 link 一次），不允许存在"只写深度"的通道 | 深度与颜色不一致（B 类） |
| L-5 | 合成阶段读取的附件版本 = 本帧绘制的版本 | 读到上一版（等价 A 类） |

## 2. 尺寸变化

以下事件会改变视口尺寸：窗口缩放、面板拖拽/最大化、DPI 变化、面板隐藏后重显。

**要求**：尺寸变化后的**第一帧**即满足 L-1～L-5，不得出现"新尺寸区域 + 旧内容"的拼接。

**实现约束**（不锁定具体 API，按优先级）：

1. 优先：让附件随当帧 `pass_size` 重建或重新适配（公开 API 即可）。
2. 次选：在检测到 `pass_size` 变化时，显式执行一次完整的颜色+深度清零。
3. 禁止：依赖"上一帧的清零仍然有效"。

## 3. 重录制（re-record）

渲染框架允许"内容未变则复用上一帧录制"的优化。该优化对本组件**不适用**：

**要求**：只要 `FrameState`（相机、关节、视口）中任一量变化，本帧就必须重新录制并重新绘制；不得复用包含旧姿态的录制。

**判定**：若审计显示残留簇与**历史姿态**重合（`HISTORIC_POSE`），即视为违反本节。

## 4. 根因分支（按 `research.md` R1 的裁决结果执行）

| 审计结论 | 追加动作 |
| --- | --- |
| `CLEAN`（仅门控生效即归零） | 无需生命周期改动；保留本节作为回归约束 |
| `HISTORIC_POSE`（跨帧累积） | 落实 §2/§3：每帧无条件清零 + 尺寸变化重建附件；完成后重跑审计应归零 |
| `CURRENT_POSE`（同帧二次深度写入） | 排查是否存在深度专用绘制路径（含外部场景/镜像/阴影误绑主附件）；移除该路径或让它同时写颜色 |

## 5. 不做的事

- 不在本契约中引入新的渲染通道、后处理链或历史缓冲（那会把一次性修复变成长期维护面）。
- 不改变 SSAA 倍率、阴影级联数量、材质公式。
- 不修改 `crates/dorobot-studio-core` 中 `RobotViewer` 的对外接口（FR-009）。

## 6. 与上游的关系

本契约描述的是"任何正确的 3D 离屏渲染都应有的行为"，因此可作为回馈 `dorobot-org/makepad-urdf-viewer` 的 PR 说明骨架：L-1～L-5 对应其 `robot_view.rs` 中 pass 的尺寸/清零/重录制三点，以及合成阶段对附件版本的读取。
